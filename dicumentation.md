1. Основная часть выполнена в модуле otus.crmcustomtabgarage
Расположение local/modules/otus.crmcustomtabgarage
Здесь реализован механизм вывода вкладки "Гараж" в Контактах.


Модуль устанавливается в систему, разворачивает необходимые таблицы и заполняет их тестовыми данными.
В результате мы получаем во CRM сущности "Клиенты".
Информация выводится с помощью штатного компонента greed: Информация выводися в табличном виде.
Функционал позволяет сортировать данные и выполнять по ним поиск.
Также присутствует возможность добавлять новые автомобили для текущего пользователя прямо из интерфейса карточки: для этого создана отдельная кнопка
"Добавить автомобиль". В контекстном меню слева(около каждого пункта есть, возможность открыть открыть окно с подробной информацией об автомобиле, удалить, автомобиль, и зайти в редактирование текущего).
Функционал кнопок работает на обработчиках BX и методах из класса компонента.
BX - выводит динамические окна, и формы, методы класса делают необходимые выборки из БД.
Класс находится в /public_html/local/modules/otus.crmcustomtabgarage/install/components/otus.crmcustomtabgarage/test.grid/test.grid/class.php
Js находится  в /public_html/local/modules/otus.crmcustomtabgarage/install/components/otus.crmcustomtabgarage/test.grid/template/.default/srcript.js

При двойном клике на автомобиль выводится подробная информация по сделкам с ним. В ней присутствует ссылка на ответственного по этой сделке пользователя.

5. Автоматическое пополнение складских запасов реализовано с помощь Агента
Агент находится по следующему адресу:
/public_html/local/php_interface/src/Crm/Market/Agent.php

Алгоритм работы следующий:
Агент срабатывает раз в день(для демонстрации настроен на поминутное выполнение)
Заходим в раздел с новарами для ремонта, получаем все товары.
Начинаем их перебирать из из стороннего сервиса https://www.random.org/integers/?num=1&min=0&max=10&col=1&base=10&format=plain&rnd=new
получаем текущее текущее количество каждой запчасти.
Если количество меньше нуля(сейчас стоит меньше 5, так как инчае для демонстрации придется долго ждать срабатывания), то автаматически происходит закупка 10 товаров данной позиции, создается заявка с пометкой "Автоматическая закупка товаров" только необходимыми товарами
Заявка сразу направляется на стадию "Завершенные"

6. Реализована ручная возможность создать заявку на пополнение недостающих товаров
Сущность "Заявка на закупку" создана на базе Смарт-процессов. 
https://cm87341.tw1.ru/crm/type/
В ней подключены: 
 - торговый каталог (для выбора необходимых товаров)
 - канбан (для отображения стадий закупки)
 - дизайнер бизнес процессов (для настрокий средств автоматизации)
 - права доступа (для настроки прав для различных пользователей)

Возможность отправлдять заявку на "Утверждение" деализована с помощью конструктора бизнес-процессов
ссылка на БП:
https://cm87341.tw1.ru/crm/configs/bp/CRM_DYNAMIC_1036/edit/7/
Алгоритм следующий:
При создании, заявка автоматически уходит на утверждение в отдел закупок. Там её долженобработать любой из закупщиков, либо начальник отдела.
При положителном исходе выполняется PHP код, который берет из заявки товары и их количество и доавляет к текущему количеству на складе.
После успешного добавления заявка переводится нв стадию "Выполнено", а автору заявки уходит уведомление об успешной закупке
При негативном исходе, закупщик должен указать причину отказа и заявка переходит на стадию "Отклонено", а автору в уведомлении приходит причина отказа.

7. Контроль незакрытых сделок по автомобилям реализован с помощь бизнес-процесса
Ссылка на БП: 
https://cm87341.tw1.ru/crm/configs/bp/CRM_DEAL/edit/8/

Алгоритм работы:
При создании сделки по автомобилю выполняется блок с PHP кодом.
По id автомобиля происходит выборка всех сделок с ним, которые находятся не на стадии "Завершено".
Если таких сдело больше одной, то текущая сделка удаляется, а пользователю уходит уведомление, что есть незакрытые сделки с этим автомобилем.
Как вариант, я рассматривал возможность создать отдельную стадию для отклоненных заявок, но в итоге остановился на удалении. 
Автоматическое удаление позволяет не забивать канбан лишними сделками и уменьшить путаницу.
